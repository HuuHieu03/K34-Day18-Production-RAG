## 3. 🚀 Lộ Trình Triển Khai Chi Tiết (Implementation Phases)

### Giai Đoạn 0: Setup & Baseline

- **Ý nghĩa**: Đảm bảo môi trường sạch sẽ, cô lập và lấy điểm mốc (baseline) để so sánh hiệu năng.
- **Nhiệm vụ**:
  - Dùng `uv` tạo `.venv` và cài đặt dependencies từ `requirements.txt`.
  - Thiết lập `.env` (cấu hình OpenAI API key).
  - Tải trước các model embedding/reranker để tránh timeout.
  - Khởi chạy Qdrant DB bằng Docker.
  - Chạy `naive_baseline.py` để lấy điểm baseline.

### Giai Đoạn 1: Module 1 - Advanced Chunking

- **Ý nghĩa**: Băm nhỏ tài liệu thông minh giúp hệ thống RAG không bị loãng ngữ cảnh và vượt giới hạn token.
- **Nhiệm vụ**: Triển khai `src/m1_chunking.py` với 3 thuật toán: Semantic, Hierarchical, Structure-Aware.
- **Kiểm thử**: Chạy `uv run pytest tests/test_m1.py -v`.

### @Giai Đoạn 2: Module 2 - Hybrid Search

- **Ý nghĩa**: Tận dụng cả sức mạnh tìm từ khóa (tốt với tên riêng, mã số) và tìm kiếm vector (tốt với ý nghĩa).
- **Nhiệm vụ**: Triển khai `src/m2_search.py` (BM25 cho Tiếng Việt + Dense Search qua Qdrant + Thuật toán gộp RRF).
- **Kiểm thử**: Chạy `uv run pytest tests/test_m2.py -v`.

### Giai Đoạn 3: Module 3 - Reranking

- **Ý nghĩa**: Loại bỏ kết quả nhiễu và đẩy các đoạn văn bản chứa câu trả lời chính xác nhất lên vị trí đầu tiên (Top-K) trước khi đưa cho LLM.
- **Nhiệm vụ**: Triển khai `src/m3_rerank.py` sử dụng mô hình Cross-Encoder (`BAAI/bge-reranker-v2-m3`).
- **Kiểm thử**: Chạy `uv run pytest tests/test_m3.py -v`.

### Giai Đoạn 4: Module 4 - RAGAS Evaluation

- **Ý nghĩa**: Áp dụng chuẩn đánh giá thế giới (RAGAS) để đo đạc khách quan chất lượng của RAG Pipeline.
- **Nhiệm vụ**: Triển khai `src/m4_eval.py` tính toán 4 chỉ số (Faithfulness, Answer Relevancy, Context Precision, Context Recall) và hàm xuất logic lỗi.
- **Kiểm thử**: Chạy `uv run pytest tests/test_m4.py -v`.

### Giai Đoạn 5: Module 5 - Data Enrichment

- **Ý nghĩa**: Làm giàu ngữ cảnh văn bản (tạo tóm tắt, sinh sẵn câu hỏi giả định) trước khi đưa vào Database để tăng tỷ lệ tìm trúng đích sau này.
- **Nhiệm vụ**: Triển khai `src/m5_enrichment.py` (Khuyến khích dùng kỹ thuật Combined Single-Call để tối ưu chi phí API).
- **Kiểm thử**: Chạy `uv run pytest tests/test_m5.py -v`.

### Giai Đoạn 6: Pipeline Tích Hợp & Báo Cáo Phân Tích

- **Ý nghĩa**: Chắp vá các mảnh ghép lại để thấy sự ưu việt của Production RAG so với Naive RAG, đồng thời rút ra bài học cá nhân.
- **Nhiệm vụ**:
  - Chạy `uv run python src/pipeline.py` để sinh báo cáo `ragas_report.json`.
  - Phân tích Top-5 lỗi nghiêm trọng nhất để điền vào `analysis/failure_analysis.md`.
  - Viết tóm lược quá trình và bài học vào `analysis/reflection_[HọTên].md`.
  - Dùng lệnh quét `grep -r "# TODO" src/m*.py` kiểm tra sạch code.
